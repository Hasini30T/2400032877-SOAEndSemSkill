# EndSemLabExam – Retrieve All Tourist Records with Token Validation

Spring Boot 3.5.7 · Java 25 · Maven · MySQL · Springdoc OpenAPI 2.8.13

`GET /api/tourists` returns all tourists **only** when the request header `Token` matches the
pre-generated token configured in `application.properties`. Otherwise it returns
**HTTP 500** with the body `Unauthorized: Invalid Token Provided`, and the database is never queried.

## Prerequisites
- JDK 25 (Eclipse must be configured to use it: *Window → Preferences → Java → Installed JREs*)
- MySQL 8.x running on `localhost:3306`
- Spring Tools for Eclipse 5.0.0.RELEASE (Maven support is built in)

## 1. Download and extract
Download `experiment.zip` and extract it. You will get a folder named `EndSemLabExam`
(it contains `pom.xml` directly inside).

## 2. Import into Spring Tools for Eclipse 5.0.0.RELEASE
1. *File → Import… → Maven → Existing Maven Projects* → **Next**.
2. *Root Directory* → Browse → select the `EndSemLabExam` folder.
3. `pom.xml` should be ticked → **Finish**.
4. Wait for Maven to download dependencies (bottom-right progress bar).
5. If you see Java-version errors: right-click the project → *Maven → Update Project…* (tick *Force Update*), and confirm JDK 25 is selected in the Installed JREs.

## 3. Configure MySQL
Open `src/main/resources/application.properties` and set your credentials:

    spring.datasource.username=root
    spring.datasource.password=your_mysql_password

(or leave the file and set environment variables `DB_USERNAME` / `DB_PASSWORD` in
*Run → Run Configurations → Environment*).

## 4. Create the database and insert sample records
Run the script `sql/tourism_db.sql`:

    mysql -u root -p < sql/tourism_db.sql

or open it in MySQL Workbench and execute it. It creates `tourism_db`, the `tourists` table and
6 sample tourists.

## 5. Configure the valid token
In `application.properties`:

    app.security.token=${APP_TOKEN:TOURIST-TEST-TOKEN-12345}

Replace `TOURIST-TEST-TOKEN-12345` with your own pre-generated token, or set the `APP_TOKEN`
environment variable. No token is generated by this app, and there is no login/registration API.

## 6. Start the application
Right-click `SoaTouristApplication.java` → *Run As → Spring Boot App* (or Java Application).
Console should show `Started SoaTouristApplication` on port 8080.
Command line alternative: `mvn spring-boot:run`.

## 7. Open Swagger UI
http://localhost:8080/swagger-ui/index.html

Expand **Tourist API → GET /api/tourists**. The `Token` header field appears under *Parameters*.

## 8. Test with a valid token
1. Click **Try it out**.
2. Enter `TOURIST-TEST-TOKEN-12345` (or your configured token) in the `Token` field.
3. Click **Execute**.
4. Expected: **200**, JSON array of all tourists.

curl:

    curl -i -H "Token: TOURIST-TEST-TOKEN-12345" http://localhost:8080/api/tourists

## 9. Test with a missing token
In Swagger, **Try it out**, leave the `Token` field empty, **Execute**
(or use curl):

    curl -i http://localhost:8080/api/tourists

Expected: **500**, body `Unauthorized: Invalid Token Provided`.

## 10. Test with an invalid token
Enter `wrong-token` in the `Token` field and **Execute**, or:

    curl -i -H "Token: wrong-token" http://localhost:8080/api/tourists

Expected: **500**, body `Unauthorized: Invalid Token Provided`.

## Automated tests (no MySQL needed)
    mvn test
`TouristControllerTest` checks 200 for a valid token, 500 + exact message for missing/invalid tokens,
and that the repository is never called when the token is bad.

## Troubleshooting
- *Access denied for user* → fix username/password in `application.properties`.
- *Unknown database 'tourism_db'* → run the SQL script first.
- Swagger omits the header if the field is empty; that is exactly the missing-token case.
